# 1. Purpose

This document defines how Aura converts business knowledge into vector
embeddings for semantic retrieval.

Embedding is responsible for transforming natural language into numerical
vectors that preserve semantic meaning.

These vectors are stored in the Vector Store and later used by AI agents
during Retrieval-Augmented Generation (RAG).

---

# 2. Goals

The embedding strategy must:

- Produce high-quality semantic vectors.
- Support multilingual content.
- Ensure deterministic indexing.
- Minimize operational cost.
- Support incremental updates.
- Allow future model replacement.
- Keep implementation simple (KISS).

---

# 3. Selected Architecture

| Component | Decision |
|------------|----------|
| Embedding Model | BAAI/bge-m3 |
| Embedding Server | Ollama |
| Deployment | Local |
| Vector Store | Supabase PostgreSQL + pgvector |
| Embedding Format | Dense Vector |
| Provider | Self Hosted |

---

# 4. Why BAAI/bge-m3

Aura selected BAAI/bge-m3 because it provides:

- Excellent multilingual support
- Strong retrieval performance
- Open-source license
- Local execution
- No API cost
- High community adoption
- Future compatibility

---

# 5. Why Ollama

Ollama provides:

- Local inference
- Easy deployment
- No cloud dependency
- No token pricing
- Stable REST API
- Simple upgrades

Aura uses Ollama only for embedding generation.

Chat generation remains handled by Gemini.

# 8. Embedding Metadata

Every embedding stores metadata.

Required fields:

- document_id
- chunk_id
- category
- language
- version
- source
- indexed_at

Optional fields:

- brand
- sku
- skin_type
- tags
- promotion_id

Old vectors remain until re-index finishes successfully.

---

# 10. Re-index Policy

Re-index occurs when:

- Product updated
- FAQ updated
- Policy updated
- Promotion updated
- Educational content updated

No re-index occurs for:

- Customer Profile
- Cart
- Wishlist
- Redis Session
- Conversation Memory

---

# 11. Failure Handling

If embedding generation fails:

Retry

↓

Retry Failed

↓

Log Error

↓

Mark Chunk Failed

↓

Continue Pipeline

One failed chunk must never stop the indexing process.

---

# 12. Performance Targets

| Metric | Target |
|----------|---------|
| Embedding Generation | <300 ms / chunk |
| Batch Embedding | <5 sec |
| Incremental Update | <5 sec |
| Full Re-index | Background Job |

---

# 13. Operational Rules

Embedding generation must be:

- Stateless
- Deterministic
- Idempotent
- Read-only

The embedding service never modifies business data.

---

# 14. Model Upgrade Strategy

Future upgrades follow:

Current Model

↓

Evaluate New Model

↓

Benchmark

↓

Full Re-index

↓

Deploy

Aura never mixes vectors generated by different models in the same index.

---

# 15. Security

Embedding service:

✓ Reads approved Business Knowledge

✓ Writes vectors

✗ Cannot access Customer Memory

✗ Cannot access Redis

✗ Cannot access Orders

✗ Cannot access Payment Data
